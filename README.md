# AstrBot 小剧场

一个用于调用 OpenAI 兼容接口生成、保存和展示 HTML 小剧场。

- 当前版本：`v1.3.1`
- 适配 AstrBot：`>=4.26.0`
- 插件目录名：`astrbot_plugin_html_theater`
- 仓库：[nikonotnicotine/astrbot_plugin_html_theater](https://github.com/nikonotnicotine/astrbot_plugin_html_theater)

## 一、什么是“小剧场”？

“小剧场”这个说法常见于 SillyTavern（酒馆）等角色扮演聊天生态。不同酒馆、不同预设对它的实现可能不完全相同，但通常可以把它理解成：

> 主线剧情之外的番外篇、独立小故事，或者一个不会自动改写主线的创意沙盒。

它适合用来测试“如果……会怎样？”的场景，例如：

- 让角色一起吃火锅、参加综艺或进行一次普通的日常约会；
- 查看角色虚构的手机记录、论坛帖子、社交媒体动态；
- 补充角色背景、兴趣、关系变化和主线没有展开的生活片段；
- 尝试不同文风、叙事视角、世界观或互动设定；
- 在不改变主线聊天上下文的情况下，快速生成一段独立故事。

因此，小剧场更像是“安全的脑洞试验场”。在本插件中，一次生成会保存成独立的 HTML 成品，并通过独立 Web 页面查看。默认情况下，生成内容不会注入当前聊天；只有开启相应配置后，才会把小剧场的一次性信息发送给当前会话 LLM。

需要注意：本插件是在 AstrBot 中提供类似的独立创作工作流。是否影响当前会话，由下面两个互相独立的开关决定：

1. `inject_conversation_context`：是否把当前聊天最近 20 条普通文字消息提供给“小剧场生成 API”。
2. `inject_after_generation`：生成完成后，是否把小剧场提示词和正文纯文字一次性发送给当前会话 LLM，让角色参考后回复。

两个开关默认都是关闭的。

## 二、插件能做什么？

- 使用 OpenAI 兼容接口生成 HTML 文档。
- 自动补全 API URL 的 `/v1/chat/completions` 后缀。
- 支持系统提示词、文风提示词、模板提示词和 Persona 人设组合。
- 支持 `{{char}}`、`{{user}}` 变量替换。
- 支持多个 Persona ID，并按照当前会话 Persona 分开编号。
- 支持使用 `/临时小剧场` 直接消费一次性提示词，不污染模板目录。
- 支持空回复、HTML 截断时最多三次补救请求。
- API 失败时显示 HTTP 状态含义和上游返回的安全错误摘要。
- 保留模型返回的完整 HTML 内容，包括外部图片、CSS、JavaScript、事件属性、表单和网络资源；只移除外层 Markdown 代码围栏并要求返回完整 HTML 文档。
- 每次生成保存为新成品，不覆盖同名文件。
- 支持重试、线性章节续写、收藏和当前 Web 页面选择。
- 提供 01—06 六个面板页面。
- 提供独立 Web 展示、可选密码和路径穿越防护；成品页面不附加插件 CSP。
- 提供完整页面数据导出/导入，不备份 API 密钥和 AstrBot 插件配置。

## 三、安装

将整个插件目录放入 AstrBot：

```text
AstrBot/data/plugins/astrbot_plugin_html_theater
```

目录中至少应包含：

```text
__init__.py
main.py
generator.py
html_utils.py
storage.py
web_api.py
web_server.py
metadata.yaml
requirements.txt
_conf_schema.json
pages/panel/
README.md
```

安装或更新后，在 AstrBot 中重载插件；如果页面仍然使用旧内容，建议完整重启 AstrBot，并在浏览器执行强制刷新（Windows 通常为 `Ctrl + F5`）。

## 四、首次配置教程

### 1. 配置 API

在 AstrBot 的插件配置页面填写：

1. `api_url`：OpenAI 兼容 API 地址。
2. `api_key`：API 密钥。
3. `model`：模型名称。

例如，服务商只给出：

```text
https://example.com
```

插件会自动请求：

```text
https://example.com/v1/chat/completions
```

如果填写的地址已经包含完整后缀，则不会重复追加。API URL、API 密钥或模型为空时，聊天指令会返回明确的配置错误，不会发起请求。

### 2. 配置 QQ 白名单

`allowed_qq_ids` 是聊天指令白名单。

- 留空：所有聊天指令返回“尚未配置白名单”错误。
- 填写 QQ 号列表：只有列表中的发送者可以使用生成、查看、重试和目录指令。
- 控制面板接口不通过这个聊天白名单判断，仍受 AstrBot WebUI 登录和页面权限控制。

### 3. 在 01 模板目录创建模板

打开插件页面的“01 模板目录”，填写：

- 小剧场标题：例如 `同人小剧场`。
- 小剧场提示词：描述希望生成的内容、文风、结构、字数和限制。

标题和提示词都必须填写。新增同名模板不会覆盖旧模板，而会自动添加编号。

插件首次运行自带三个默认模板；如果你已经添加过模板，旧模板和页面数据会保留。

### 4. 在 03 人设配置设置 Persona

建议先确认当前 AstrBot 会话使用的真实 Persona ID，再在页面输入完全一致的 ID。Persona ID 区分大小写和拼写。

每个 Persona 可以保存：

- char 人设名字；
- char 人设内容；
- user 人设名字；
- user 人设内容。

可以点击“＋”新增多个 Persona。编辑时 Persona ID 不直接改名；如需改名，请新增一个 Persona，再删除旧配置。

### 5. 发送第一条指令

例如：

```text
/生成小剧场 同人小剧场
```

成功后，插件会保存 HTML 成品，并把它设为当前 Web 展示项。Web 未开启时，会返回成品标题和本地保存路径；Web 开启时，会附带访问地址。

## 五、完整配置说明

| 配置键 | 作用 | 默认值 | 注意事项 |
| --- | --- | --- | --- |
| `api_url` | OpenAI 兼容接口地址 | 空 | 自动补全 `/v1/chat/completions` |
| `api_key` | API 密钥 | 空 | 不写入页面备份，不进入调试日志 |
| `model` | 模型名称 | 空 | 必须是服务商支持的模型 |
| `html_save_path` | HTML 保存目录 | 空 | 留空使用插件数据目录 |
| `web_enabled` | 是否开启独立 Web | `false` | 关闭时仍会保存 HTML |
| `web_host` | Web 监听地址 | `127.0.0.1` | VPS 对外监听可填 `0.0.0.0` |
| `web_port` | Web 监听端口 | `7315` | 被占用时请换端口 |
| `web_password` | Web 访问密码 | 空 | 留空表示不启用密码 |
| `theater_system_prompt` | 小剧场系统提示词 | 内置 HTML 提示词 | 控制输出格式和生成行为 |
| `style_prompt` | 小剧场文风提示词 | 空 | 留空时不追加文风提示 |
| `continue_on_empty` | 空回/截断补救 | `true` | 最多补救三次，仍失败则不保存残缺文件 |
| `inject_after_generation` | 生成后注入当前会话（没测） | `false` | 只对触发指令的当前会话生效 |
| `inject_conversation_context` | 生成时注入聊天上下文（没测） | `false` | 最多最近 20 条普通 user/assistant 文字消息 |
| `inject_memory_and_diary` | 核心记忆与近 N 天日记（甚至没写） | `false` | 首版仅保留配置项，暂不读取或注入 |
| `retention_limit` | 未收藏成品保留数量（没测） | `6` | 收藏成品不受自动清理影响 |
| `debug_enabled` | 插件调试日志 | `false` | 开启后增加插件 DEBUG 诊断，不修改全局日志级别 |
| `allowed_qq_ids` | QQ 聊天白名单 | 空 | 为空时聊天指令直接报错 |

内置系统提示词要求返回完整 HTML 并按小剧场提示词实现页面。生成请求会明确告诉模型：提示词要求的外部图片、CSS、JavaScript、事件属性、表单和网络行为都应原样实现；旧配置中的资源限制也不会再由插件清理生成结果。

### 图片、脚本与样式规则

- 图片、样式、脚本和其他资源完全按当前小剧场提示词及模型输出处理，不再做 URL 白名单或标签属性清理。
- 生成结果会直接保存和展示；模型可以选择内联资源或外部 CDN 资源，也可以实现提示词要求的表单、事件属性和网络交互。
- 控制面板预览 iframe 仍使用 `sandbox="allow-scripts"`，不授予 `allow-same-origin`；独立 Web 成品页面不附加插件 CSP。

## 六、一次生成的处理流程

生成请求按以下顺序组装，不携带普通聊天历史（除非开启 `inject_conversation_context`）：

```text
小剧场系统提示词
        ↓
文风提示词（可选）
        ↓
用户选择的模板提示词
        ↓
最近 20 条普通会话文字（可选）
        ↓
页面 Persona 人设，或当前会话 Persona 人设
        ↓
OpenAI 兼容 API
        ↓
原样保存 HTML → 更新当前 Web 展示项
```

如果开启 `inject_after_generation`，生成成功后还会额外向当前会话 LLM 发送一次：

- 小剧场提示词；
- 小剧场 HTML 提取出的纯文字；
- 内置提示“请参考这个小剧场回复，不要 OOC”。

这次注入只发送到触发指令的会话，不会把模板目录或成品目录暴露给 Persona，也不会持续注入后续普通消息。

## 七、Persona、变量和命名规则

### 变量替换（没测）

模板和人设中支持：

```text
{{char}}
{{user}}
```

优先级如下：

1. 页面 Persona 配置中的 char/user 名字；
2. 当前会话 Persona 名字和触发者昵称。

即使只填写 user 名字、不填写 user 人设内容，也可以正常替换 `{{user}}`。

### 成品标题

普通生成按照 Persona ID 和模板标题独立编号：

```text
Persona1同人小剧场1
Persona1同人小剧场2
Persona2同人小剧场1
```

重试会沿用原请求快照中的 Persona ID，并生成下一个编号。

### 续写章节（如测）

同一个基础成品使用线性章节编号：

```text
Persona1同人小剧场1-chapter1
Persona1同人小剧场1-chapter2
Persona1同人小剧场1-chapter3
```

章节编号记录在元数据中，不依赖文件名猜测；即使删除基础成品，已有章节仍能继续识别所属系列。

## 八、六个控制面板页面

控制面板支持手机屏幕：窄屏下导航自动换行，模板和成品表格会变成纵向字段卡片，表单、操作区和预览窗口按触控布局显示，不需要横向拖动整张表格。

### 01 模板目录

- 搜索标题或提示词；
- 新增、编辑模板；
- 多选并批量删除；（没测）
- 同名模板自动编号；
- 标题和提示词由服务端再次校验，不能保存空值。

### 02 成品与续写（没测过续写）

- 查看生成和续写成品；
- 查看 Persona、章节和生成时间；
- 预览生成的 HTML；
- 收藏/取消收藏；
- 删除成品；
- 选择当前 Web 页面显示项；
- 选择源成品并生成下一章节。

面板续写不会读取当前聊天上下文，也不会向 QQ 会话注入。

### 03 Persona 人设配置（没测过多个人格）

- 通过“＋”增加多个 Persona；
- 页面刷新后恢复上次选择；
- 保存 char/user 名字和内容；
- 删除指定 Persona 配置；
- 列出 AstrBot 已知 Persona 供参考。

### 04 小剧场备份（这也没测嘻嘻）

备份 ZIP 包含：

- 所有模板和提示词；
- 所有生成/续写 HTML；
- 成品索引和纯文字摘要；
- 收藏状态；
- 当前 Web 展示项；
- 全部 Persona 页面配置；
- 05 页面颜色和自定义 CSS。

备份不包含：

- API URL、API 密钥、模型配置；
- Web 密码、QQ 白名单；
- AstrBot 其他配置；
- `_conf_schema.json`；
- 当前聊天上下文。

导入支持：

- 安全合并：同名模板和成品自动编号，不覆盖当前页面数据；
- 完整恢复：需要输入“完整恢复”二次确认，并先生成可回滚备份。

### 05 CSS 颜色配置

提供四种保持新拟态风格的配色：

- 粉白：柔和粉色与白色高光；
- 黑白：高对比黑白灰；
- 蓝白：默认冷静蓝白；
- 灰白：低饱和中性灰白。

（没测试自定义）在“自定义插件面板 CSS”文本框中输入 CSS 后会立即应用。例如：

```css
.panel-card {
  border-radius: 34px;
}

.nav-item.active {
  letter-spacing: 0.08em;
}
```

自定义 CSS 会自动保存到页面状态，单次最多保存约 128KB。它只用于插件控制面板，不会注入生成 HTML。

### 06 收藏夹

集中显示所有已收藏成品，可以：

- 查看标题、Persona、时间和正文摘要；
- 预览 HTML；
- 设为当前 Web 展示项；
- 取消收藏。

收藏成品不会被 `retention_limit` 自动清理。

## 九、聊天指令（嗯只测了一半。gpt5.6luna评价：懒得喷了。）

所有聊天指令都要求发送者在 `allowed_qq_ids` 中。

```text
/生成小剧场 <模板标题>
```

按标题生成指定模板。模板标题支持空格，例如：

```text
/生成小剧场 超同人小剧场
```

```text
/小剧场 <模板标题>
```

`/生成小剧场` 的兼容别名。

```text
/临时小剧场 <提示词>
```

直接使用本次提示词生成类型为“临时小剧场”的成品，不会在模板目录新增记录。生成的 HTML 仍会进入成品列表，可预览、收藏、续写、备份，并受 `retention_limit` 管理。例如：

```text
/临时小剧场 {{char}} 和 {{user}} 被困在只营业一晚的午夜书店
```

临时小剧场成功生成后，也可以使用 `/小剧场 重试` 重新生成。

```text
/生成随机小剧场
```

从当前模板目录随机选择一个模板。

```text
/小剧场 重试
```

重新使用上一次成功发起生成时的模板、Persona、上下文和配置快照。配置变化不会改变这次重试的人物和模板上下文。

```text
/小剧场目录
```

返回当前模板标题列表。

```text
/查看小剧场 <模板标题>
```

只返回模板标题和提示词，不返回已经生成的 HTML。

常见错误：

- `尚未配置 QQ 白名单`：需要在插件配置中填写 `allowed_qq_ids`；
- `不在 QQ 白名单中`：当前发送者没有权限；
- `未找到小剧场模板`：检查标题、空格和模板是否已在页面保存；
- API 配置缺失：检查 URL、密钥和模型；
- API 请求失败：错误会同时显示 HTTP 状态含义及上游的 `error.message`、`message`、`detail` 或错误代码；例如 401 通常是密钥无效，404 通常是地址、路径或模型不存在，429 通常是频率或额度限制；
- API 返回无效 JSON：检查 API URL 是否指向 OpenAI 兼容的 `/chat/completions` 接口；
- 空回/截断补救失败：接口多次没有返回完整 HTML，需要查看 API 服务端响应或打开调试日志。

## 十、Web 展示

开启 `web_enabled` 后，默认访问：

```text
http://127.0.0.1:7315/
```

如果监听地址填写 `0.0.0.0`，请使用服务器实际 IP、反向代理域名或端口映射地址访问，不要直接打开 `0.0.0.0`。

设置 `web_password` 后，访问页面会先显示密码登录页，并通过安全 Cookie 维持登录状态。

Web 页面只展示插件保存的 HTML，不允许通过 URL 访问 HTML 保存目录之外的文件。成品页面不附加插件 CSP；控制面板预览仍保留 iframe sandbox 隔离。

## 十一、“未找到该路由”排查（没找到就重启）

如果面板提示：

```text
未找到该路由
```

通常是插件代码已经更新，但 AstrBot 进程仍使用旧插件实例，旧实例没有注册新增页面 API。处理步骤：

1. 在 AstrBot 中完整重载 `astrbot_plugin_html_theater`；
2. 如果仍然提示，重启 AstrBot；
3. 浏览器执行 `Ctrl + F5`，清除旧版面板 JavaScript 缓存；
4. 确认插件版本已经显示为 `v1.3.1`。

从 v1.2.1 开始，页面路由在插件实例初始化时注册，热重载后不会再依赖一次性的全局加载事件。05 配色保存接口是：

```text
/api/plugins/extensions/astrbot_plugin_html_theater/preferences/save
```

正常使用时不需要手动访问这个地址。
